# セキュリティ設計・検証記録

確認日：2026-11-06。脅威検出の保証や第三者による侵入試験ではありません。ソースレビュー、依存監査、合成画像による自動試験の結果です。

## データと通信

| 対象 | 保存先・通信 |
|---|---|
| 選択した写真 | 処理中のメモリ。原本保存を選んだ場合だけIndexedDB |
| OCR全文 | メモリのみ。画面を閉じる/次の画像へ進むと参照を解放。永続保存しない |
| 構造化項目、カード設定 | IndexedDB。許可フィールドのみ再構築して保存 |
| カード | ブランド・下4桁・別名・所有者のみ。フル番号/CVV/有効期限の専用保存項目なし |
| バックアップ | AES-GCMで暗号化して利用者の端末へダウンロード |
| CSV | 利用者の明示操作で平文ダウンロード。事前警告あり |
| ネットワーク | 初期配信、全OCR資産のキャッシュ、Service Worker更新確認など、同一オリジン静的GETのみ |

アプリからのレシートPOST、外部AI/OCR API、Google接続、広告、分析SDK、ビーコン、WebSocket、外部フォントは実装していません。配信サービスにはアクセス日時/IPなど通常のHTTPアクセス情報が届き得ます。ブラウザ/OSの独自通信・ユーザーが選んだクラウド保存先の通信はアプリから制御できません。

本番CSPは `default-src 'self'`、`script-src 'self' 'wasm-unsafe-eval'`、`worker-src 'self'`、`connect-src 'self' blob:` 等。WASM実行に必要な許可は付けますがJavaScriptの通常の`unsafe-eval`は許可しません。HTMLのインラインscript、外部script、object、form送信を禁止します。画像のblob/data URLはプレビューに使用します。

TesseractのWorkerはblobで作らず、同一オリジンの固定URLから起動。workerPath/corePath/langPathを明示指定し、ライブラリ既定のCDNを使わない設定です。モデルキャッシュはTesseract側では無効化し、Service Workerの静的資産キャッシュに統一しています。

GitHub Pagesでは任意のHTTPセキュリティヘッダー設定ができないため、CSPはHTML metaです。`frame-ancestors`、HSTS等を本アプリから設定しているとは主張しません。同一オリジンの別JSファイルとして起動するWorker自身にHTTP CSPを付与することもPagesではできず、将来の悪意あるWorker更新をHTMLのCSPだけで封じ込めることはできません。依存固定・更新レビュー・実通信監査が重要です。

## 保存・出力の防御

- Reactのテキスト描画を使用。HTMLとしてユーザー入力を挿入しません。
- 保存時/復元時に同じ許可項目の検証を実施。未知のプロパティは捨てます。
- 下4桁は4桁のみ。自由記入欄も13〜19桁の連続/区切り付き番号やCVV/有効期限を示す文字列を拒否します。全角数字も正規化して検出します。これは任意の個人情報を完全検出する仕組みではないため、不要な情報は入力しないでください。
- 画像自体のカード番号・顔・住所・EXIFを自動消去しません。原本保存は初期オフ、保存時に注意を表示します。
- 金額は十進文字列→BigIntの最小単位。浮動小数で合算しません。
- CSVは引用符・改行のエスケープと、数式開始文字のアポストロフィ防御を実施します。
- バックアップはPBKDF2-SHA256 310,000回、salt16バイト、AES-256-GCM、IV12バイト、バージョン用AAD。暗号化キーはメモリのみ。
- 復元は暗号認証、サイズ、型、通貨、金額、ID重複、画像の先頭形式等を検査してから、全体を1トランザクションで置換します。復元前には内容件数と置換確認画面を表示します。
- アプリコードにconsoleログはありません。テストのログは同梱した架空画像の所要時間等のみです。

| Chrome UIでカード登録→保存→編集→CSV→暗号化→全削除→復元 | 成功 |
| Chrome UIでXSS文字列を保存・再表示 | 文字列として表示。script発火なし |
| オフライン再読み込み→実OCR→IndexedDB保存→再読み込み | 成功 |

発見・修正した問題：暗号化バックアップのbase64上限をパディング込みに修正。静的配信テストサーバーの `Vary: Origin` によりキャッシュが一致しなかった問題を、同一オリジンのビルド所有資産のみのキャッシュでignoreVaryを使って修正。カードの伏字がs/k/o等にOCR誤認識されるケースはブランドと末尾4桁を限定照合し「要確認」にしています。

## 依存関係

直接依存はバージョン固定、間接依存はpnpm-lock.yamlの整合性情報で固定。Tesseract.js/coreはApache-2.0、React系はMIT。英語モデルのnpmパッケージはMIT表記ですが、元のTesseract学習データはApache-2.0で、配布通知に別途その出典を記載します。[モデル元のLICENSE](https://github.com/tesseract-ocr/tessdata/blob/main/LICENSE)。開発用sharp/libvipsにLGPL系ライセンスがありますが、これらのネイティブバイナリはブラウザ配布物には含めず、アイコン/架空画像のビルドにのみ使用します。

`docs/dependencies.json` は今回導入された環境のパッケージを記録します。Linux CIではプラットフォーム依存パッケージが異なるため、ビルド時に再生成します。通知文は `public/THIRD-PARTY-NOTICES.txt`。OCRファイルのSHA256は `public/ocr-assets.json`。既知脆弱性0件は安全の完全な保証ではありません。

更新時はlockfile差分・ライセンス・公式リリースノートを確認し、`pnpm audit`、単体テスト、ビルド、静的監査、オフライン実OCRを再実行します。依存更新botによる自動マージは設定していません。GitHub Actionsの参照はコミットSHAに固定しています。

## 残る限界

- IndexedDB内のデータはアプリ独自には暗号化していません。端末ロック/OS暗号化と安全なブラウザを使用してください。端末の侵害、同一オリジンの悪意あるコード、利用者が導入した拡張機能への防御は完全ではありません。
- ブラウザ設定変更、容量不足、OSの解放処理、サイトデータ削除で失われ得ます。`persist()`が許可されても手動削除を防げません。
- iPhone Safariでのメモリ圧迫、バックグラウンド中の中断、カメラ/HEIC、実際の感熱紙の認識精度は未検証。縮小前のブラウザ画像デコードは元画像分のメモリを必要とします。
- 画像入りバックアップはbase64化に追加メモリが必要。大きなデータセットのストリーミングは未実装です。
- 厳密な画面ロック、アプリ内PIN、生体認証、端末間同期、データ復旧サーバーはありません。

安全境界や未検証項目を踏まえ、実機でバックアップ・復元まで確認してから利用してください。
