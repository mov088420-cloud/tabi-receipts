# Googleスプレッドシートへの自動保存

初期状態はオフです。撮影 → OCR → 原本と確認 →「確認して保存」の後に、専用の表へ項目・商品明細・撮影日時を送ります。写真の原本、OCR全文、登録した全カードの一覧は送りません。初回設定後は同じ表へ保存します。

**実装と架空データによる試験は完了しています。実Googleへの接続、Apps Scriptの実デプロイ、iPhone Safariの実通信はまだ未検証です。接続確認が成功するまでは自動保存を有効にしません。**

## 最初の設定（Macでの操作推奨）

1. 保存先に使うGoogleアカウントで [Apps Script](https://script.google.com/home) にログインし、「新しいプロジェクト」を選びます。プロジェクト名は「旅のレシート帳 自動保存」などにします。
2. アプリの「設定 → Googleスプレッドシートに自動保存 → 初回の接続手順」から「Google側の設定コードを保存」を押します。ダウンロードした `Code.gs.txt` の全内容を、Apps Scriptの `Code.gs` に貼り付けて保存します。ソースにも [Code.gs](../integrations/google-apps-script/Code.gs) があります。
3. エディタ上部の関数一覧で `setup` を選び、1度実行します。Googleの権限画面で、自分が作成したプロジェクトであることと、スプレッドシートへのアクセス範囲を確認して許可します。安全性を確認できない警告が出た場合は、その画面を確認してから進めます。
4. 自分のGoogleドライブに「旅のレシート帳」という専用のファイルが作成されます。「レシート一覧」「商品明細」タブが保存先です。表を「リンクを知っている全員」に公開する必要はありません。
5. Apps Scriptの「プロジェクトの設定 → スクリプト プロパティ」で `TABI_KEY` をコピーします。64文字の連携キーです。チャット、公開リポジトリ、表のセルには貼りません。`TABI_SHEET_ID` は固定保存先です。通常は変更しません。
6. 「デプロイ → 新しいデプロイ → 種類を選択 → ウェブアプリ」。実行するユーザーは「自分」、アクセスできるユーザーは「全員」を選んでデプロイします。組織アカウントでこの設定が禁止されている場合、管理方針を回避せずCSVを使ってください。
7. ウェブアプリのURL（`https://script.google.com/macros/s/.../exec`）をコピーします。ライブラリURL、エディタURL、`/dev` のテストURLは使いません。
8. **レシートを保存するiPhoneのホーム画面アプリ内**で、設定にURL・連携キーを入力。Googleへの自動送信とキー保存にチェックして「接続を確認して有効にする」を押します。
9. 「保存先のスプレッドシートを開く」で自分の専用表であることを確認します。接続成功だけでは以前のレシートは送りません。必要なら「保存済みの全レシートも送信」を押します。
10. 架空の手入力レシートを1件保存し、表へ届くこと、編集して再保存すると同じ行が更新されること、商品明細も更新されることを確認します。原本を選んでもGoogleへ送るのは項目だけです。

Google Driveの接続ツールはファイルの検索等に使えますが、アプリ用のApps Scriptデプロイや実行権限の代わりにはなりません。端末ごとに接続設定が必要です。Google側のコードを修正した場合は、「デプロイを管理」から新バージョンをデプロイしてください。

## 自動保存の動き

- 先に端末内へ保存します。ネット接続・Google側の応答を確認してから「Googleスプレッドシートへの保存を確認しました」と表示します。
- 失敗時・オフライン時は送信待ちを保持します。アプリ表示中は60秒ごと、オンライン復帰時、画面に戻った時に再送します。「今すぐ再送」も使えます。閉じている間は送信しません。
- 同じレシートIDの再送は同じ行を更新します。通信が切れて結果を受け取れなかった場合も重複させません。ヘッダーや更新番号・更新IDの列は変更しないでください。
- Google側で表を直接編集した内容は端末へ戻りません。同じレシートをアプリで保存し直すと、そのレシートの行・明細はアプリの内容で更新します。
- 端末内での削除はGoogle側を削除しません。表からの削除が必要ならGoogle側でも削除します。送信開始済みの処理は、接続解除直後も完了する場合があります。
- 金額と数量はGoogle側では数値として保存します。通貨ごとに集計してください。Google Sheetsの計算は表計算エンジンの数値演算で、アプリ内のBigInt検算とは別です。
- 1万レシート、商品明細約5万行までの上限を設けています。Googleの実行時間・利用枠など、これより先に制限に達する場合もあります。

## 撮影日時

JPEGのEXIF撮影情報を優先します。タイムゾーンがある場合は `2026-11-07T14:30:00+08:00` のように残します。+08:00はシンガポール、+09:00は日本です。オフセットのないEXIFはタイムゾーン不明のまま残します。

日時情報がないカメラ入力では、シャッターを押した時刻ではなく、写真をアプリへ戻した時刻を「目安」と明示します。写真ライブラリ入力で日時情報が取れない場合は撮影日時を空欄にし、取り込み日時を残します。HEIC・PNG・WebPの撮影メタデータ解析は今回未対応です。必要なら確認画面で撮影日時を修正できます。取引日時や登録日時とは別の項目です。

## 停止・復元・キー管理

「自動送信を停止する」で、端末にある接続設定・キー・送信待ちを削除します。レシートとGoogle側の表は残ります。バックアップ復元・全データ削除でも自動送信は停止します。接続情報はバックアップに含めません。

Google側を完全に停止するにはApps Scriptのデプロイをアーカイブします。キーが漏れた可能性がある場合は、Script Propertiesの `TABI_KEY` を削除して `setup` を再実行し、新しいキーで各端末を接続し直します。表の共有権限も確認してください。

## 実機で確認する項目

- iPhoneから接続確認が成功し、設定した表へのリンクが正しい。
- 1件保存・再保存・商品明細変更で1件のレシート行を維持する。
- 機内モードで保存 → アプリを閉じて再起動 → 通信を戻すと送信できる。
- Google側の公開設定を変えた場合やキー不一致で「保存済み」と表示しない。
- Google側だけ成功して応答を受け取れなかった場合も、再送で重複しない。
